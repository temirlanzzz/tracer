Where did this text come from?

Paste a passage and the places you suspect it came from. Tracer sorts them into exact copies, near-duplicates and paraphrases, highlights the matching words, and dates each source with evidence the page can't fake: when the Wayback Machine first saw it.

    How it works

    Every candidate goes through the same steps, all in this tab unless you point it at a server.

    1. Text in. Pasted text is used as is. A Wikipedia URL is fetched through the Wikipedia API, which allows cross-origin reads. Any other URL is tried directly; when the site blocks it (most do), the card says so and asks you to paste the text.
    2. Lexical match. Both texts are lower-cased, stripped of punctuation and diacritics, and cut into overlapping 5-word shingles. I compute the exact Jaccard of the two shingle sets, a 128-permutation MinHash estimate of it, and containment: the share of the suspect's shingles found in the candidate. Containment is the one that decides, because a copy usually sits inside a bigger page full of navigation and other text.
    3. Paraphrase. Lexical overlap can't see a rewrite, so MiniLM (all-MiniLM-L6-v2, 8-bit, run by transformers.js in a Web Worker) embeds the suspect in passages of at least 12 words, and every candidate sentence once; a window of 1–3 consecutive candidate sentences is the word-weighted mean of their vectors, because a paraphrase merges and splits sentences. The semantic score is the share of suspect words whose passage has a candidate window at cosine ≥ 0.60. Those passage pairs get a dotted underline in the side-by-side view.
    4. Class. Containment ≥ 0.90 is an exact copy. ≥ 0.40 (or Jaccard ≥ 0.40) is a near-duplicate. Otherwise, semantic coverage ≥ 0.35 is a paraphrase, and containment ≥ 0.05 is a partial quote. Anything below that is unrelated.
    5. Dates. For URLs I ask the Wayback Machine when it first captured the page. Wikipedia pages also get the timestamp of their first revision. What the page says about itself is shown too, but only as a claim. The origin is the related source with the earliest independent date. Self-reported dates only count when nothing independent exists.

    The server in the repo runs the same pipeline in Python with the same hash functions (a parity test checks the browser and server agree bit for bit). It adds web search (DuckDuckGo HTML, or Brave/SerpAPI with a key), full-page fetch with trafilatura, htmldate for the page's claimed date, and Wayback CDX for exact first-capture timestamps.

    What I learned

    Page metadata lies, in both directions. pemberley.com says 2004 and authorama.com says 2025, but the archive saw them in 1998 and 2004. It goes the other way too: Gutenberg's printed release date (1998) is earlier than the archive's first capture of that URL (2008), and it's probably true, since the file just moved. That's why the tool only falls back on claims, and why it calls an archive date an upper bound rather than "the" date.

    Containment, not Jaccard, decides "copy". Both real copies score Jaccard below 0.40, because the copied passage sits inside a page with navigation and the rest of the chapter. Jaccard would have labelled two verbatim copies as merely "near". The right question is what share of the suspect is found inside the candidate.

    Sentence-by-sentence embeddings miss paraphrases. My first version averaged the best sentence-to-sentence cosine. That scored my retelling 0.55 and the Wikipedia plot summary 0.42, too close to separate. Rewrites merge and split sentences, so now I compare suspect passages against 1–3 sentence windows of the candidate and count how much of the suspect has a match at ≥ 0.60. That gives 0.52 against 0.18. Building each window from averaged sentence vectors gives the same scores and cut the browser embedding time from 58 s to about 10 s.

    CORS shapes the product. Browsers can't read the archive's best endpoint (CDX) or almost any source page. A static demo has to be built around the few open doors: Wikipedia's API and the Wayback availability API. The full pipeline lives in the server.

    Limits

    What the browser version can't do. I checked each endpoint with curl -H "Origin: https://temirlanzzz.github.io":

    • web.archive.org/cdx/search/cdx: no CORS header, so browsers can't read it. This is the exact first-capture API, and only the server uses it.
    • web.archive.org/web/<ts>id_/<url> (raw archived pages): no CORS header, so browsers can't read old page text.
    • wayback-api.archive.org/wayback/available: sends Access-Control-Allow-Origin: *, so it works. It only answers "the closest capture to T", so the browser probes Jan 1 and Jul 1 of each year from 1996. The answer is the earliest capture those probes hit, which is an upper bound. Sometimes the API returns nothing, or an HTML "Temporarily Offline" page that fails CORS; the UI says so when that happens. (archive.org/wayback/available timed out from my network, so I use the wayback-api host.)
    • Page text: only Wikipedia (its API sends CORS headers) and the rare site that allows cross-origin reads. For anything else you paste the text. In the example, the pemberley.com and Gutenberg texts were captured by my build script and are labelled that way. The "recorded CDX" dates next to them come from a server run on 2026-10-14.
    • No web search. Search engines don't allow cross-origin calls without a key you would have to expose, so finding candidates is a server feature.

    Both versions. The thresholds (0.90 / 0.40 / 0.05 containment, 0.35 semantic coverage) are tuned on one example, not on a labelled benchmark. The paraphrase margin is modest (0.52 vs 0.18), and MiniLM will call a close summary of the same scene a paraphrase. The two sources marked "written for this demo" are mine, made to show a near-duplicate and a paraphrase. The server's embeddings are optional (requirements-embeddings.txt pulls in PyTorch). Without them it reports semantic: null and can't see paraphrases, and that path isn't covered by the tests. A first capture tells you when the archive noticed a page, not when someone wrote the text: this one was written in 1813.
